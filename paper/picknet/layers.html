PickNet, Layer by Layer

The three learned parts of PickNet drawn out in full: the history encoder, the deck head and the pack decoder. Every box with weights shows its tensor shape and its parameter count for the 8.4M all-sets model.

Bdrafts in a batch (128)
T = 45pick slots: 3 packs × 15
P = 15card slots in a pack
d = 256width of every vector
h = 8attention heads
dh = 32width of one head (256 / 8)

1 · The history encoder

Input: 45 tokens per draft, shape [B, 45, 256]. Token t is the sum of the slot's position vector, the bag of pack t, the card taken at t−1, the bag of cards the other drafters took, the context MLP and the set vector. At this point each token only knows its own slot.

The encoder is nn.TransformerEncoderLayer(256, 8, 1024, 0.05, batch_first=True, norm_first=True) stacked 4 times, each copy with its own weights. One layer is drawn below.

Step by step, with shapes

  1. LayerNorm 1. For each of the B×45 tokens, subtract the mean of its 256 numbers, divide by their standard deviation, then apply learned scale γ and shift β (256 each).
  2. W_qkv. One Linear(256, 768) produces Q, K and V at once. That is the same as three 256×256 maps, packed together for speed.
  3. Split heads. Reshape each of Q, K, V from [B, 45, 256] to [B, 8, 45, 32]. Each head gets a 32-number slice and works independently.
  4. Scores. Q Kᵀ / √32 gives [B, 8, 45, 45]: for each head, how strongly token t matches token j. Dividing by √32 keeps the scores at unit scale, so the softmax does not saturate.
  5. Causal mask. Scores above the diagonal (j > t) become −∞, so they get zero weight after the softmax.
  6. Softmax across each row. Row t is now a set of weights over tokens 0…t that sum to 1.
  7. A · V. Each token takes the weighted average of the values it attends to. Shape [B, 8, 45, 32].
  8. Concat + W_o. Put the 8 heads back side by side ([B, 45, 256]), then a Linear(256, 256) mixes what the heads found.
  9. Dropout, then add to the residual stream: x = x + attn(LN1(x)).
  10. MLP. x = x + Linear(1024→256)(Dropout(ReLU(Linear(256→1024)(LN2(x))))), applied to each token on its own. Default activation in PyTorch's encoder layer is ReLU. Section 4 takes the MLP apart.

After the 4th layer the stream goes through hist_norm, a final LayerNorm. Pre-LN layers never normalise the residual stream itself, so this last norm puts h on a steady scale before the decoder and deck head read it. GPT-2 has the same final norm.

2 · The deck head

A training aid taken from puder's model. From state t, it predicts which of the cards already picked will end up in the drafter's main deck. It gives the encoder a second, denser signal: to answer well, h_t has to know the drafter's colours and plan, which is exactly what helps the pick. It is switched on by deck_w = 0.3 and ignored at inference.

# picknet.py
def deck_logits(self, h, tab, pick):
    q, k = self.deck_q(h), self.deck_k(F.embedding(pick, tab))   # [B,45,256] each
    return q @ k.transpose(1, 2) / q.shape[-1] ** 0.5          # [B,45,45]

# train_picknet_all.py
m = (t > j) & valid[:, :, None] & known[:, None, :]
w = m * ((t + 1) / T)
bce = F.binary_cross_entropy_with_logits(dl, y[:, None, :].expand_as(dl), reduction="none")
deck = (bce * w).sum() / w.sum()
loss = nll + 0.3 * deck

This is a bilinear head: no attention, no softmax across cards. Each (t, j) cell is its own yes/no question, which is why the loss is binary cross-entropy and not a softmax. Because deck_k reads the shared card table, its gradient also shapes the card vectors.

3 · The pack decoder

Now the model scores the cards it could take. Every pick slot has up to 15 candidates, so the decoder works on a 4-D tensor [B, 45, 15, 256]: all 45 picks of a draft are scored in one pass.

The encoder made one vector per pick, h_t, summing up what the drafter knew at that moment. The decoder makes one vector per candidate card and asks of each: "given this drafter, and given the other cards in this pack, how likely is a human to take this one?" It does that in four stages:

  1. Build a token per card: card identity + number of copies + the drafter's state at that pick.
  2. Let the cards in a pack compare with each other (self-attention).
  3. Let each card look back at the draft up to that pick (cross-attention to h).
  4. Turn each card into one number, then softmax over the pack to get pick probabilities.

Stages 2 and 3, plus an MLP, form one decoder block, and the block is repeated 3 times. Shape stays [B, 45, 15, 256] from the first stage until the score head squeezes it to [B, 45, 15].

Building the candidate tokens

  1. Card vector. idx is [B, 45, 15]: the card id in each slot of each pack, with a padding id for empty slots. Looking it up in the card table gives [B, 45, 15, 256]. This is the same table the encoder used for its bags, so a card means the same thing on both sides. The padding row is all zeros.
  2. Copies vector. cnt is how many copies of that card are in the pack. It is clamped to 3 and looked up in copies, a 4-row table: row 0 for empty slots, then 1, 2 and 3+ copies. Same shape as the card vector.
  3. State vector. state_proj is a Linear(256, 256) applied to h ([B, 45, 256]). Adding a new axis gives [B, 45, 1, 256], which broadcasts across the 15 cards. Every card at pick t now carries the same summary of the drafter: colours, curve, what has been flowing. The projection lets the model put that summary in a different subspace from the card vectors so the two don't blur together.
  4. Add the three. x = card + copies + state, shape [B, 45, 15, 256]. At this point a card knows who it is and who is drafting it, but not what else is in the pack.
  5. Pad mask. pad = cnt > 0, shape [B, 45, 15], True for real cards. Packs shrink as the round goes on, from a full pack at the first pick down to one card at the last, so later rows are mostly padding. One edge case: if a pack is entirely empty (a missing P1P1 in the logs), slot 0 is marked real anyway so attention never sees a row with nothing to attend to. That pick is excluded from the loss.

One decoder block, repeated 3 times

Step by step, with shapes

Sublayer 1: self-attention within the pack.

  1. LayerNorm 1 on each card's 256 numbers.
  2. W_qkv. Linear(256, 768) gives Q, K and V together, [B, 45, 15, 768].
  3. One pack per row. Reshape to [B·45, 15, 768]. The batch axis now counts packs, not drafts, so attention can only mix cards that are in the same pack at the same pick.
  4. Split heads. [B·45, 8, 15, 32] for each of Q, K, V.
  5. Scores. Q Kᵀ / √32 gives [B·45, 8, 15, 15]: how much each card wants to read each other card in its pack.
  6. Pad mask. pad is reshaped to [B·45, 1, 1, 15] and broadcast over heads and query rows, so every card ignores the empty slots as keys. There is no causal mask here: a pack is a set, and every card may see every other card.
  7. Softmax, then A · V: [B·45, 8, 15, 32].
  8. Concat + W_o. Heads back side by side and reshape to [B, 45, 15, 256], then o1 = Linear(256, 256).
  9. Dropout, then add to the residual: x = x + selfattn(LN1(x)).

Sublayer 2: cross-attention to the history.

  1. LayerNorm 2, then queries from the cards: q2 = Linear(256, 256).
  2. Flatten the cards. Reshape to [B, 45·15, 256] = [B, 675, 256], then split heads to [B, 8, 675, 32]. Now each draft is one long list of 675 card queries.
  3. Keys and values from the history: kv2 = Linear(256, 512) on h, split into K and V, each [B, 8, 45, 32]. No LayerNorm here because h already went through hist_norm. Since h is the same in every block, each block just learns a different way to read it.
  4. Scores. [B, 8, 675, 45]: how much each card wants to read each of the 45 history states.
  5. Causal mask. see is [45, 45] with True on and below the diagonal. repeat_interleave(15, 0) copies each row 15 times to make [675, 45]: row 15·t+c is card c at pick t, and it gets row t of the mask. So a card at pick t can read states 0…t and nothing later.
  6. Softmax, then A · V: [B, 8, 675, 32].
  7. Concat + W_o. Back to [B, 45, 15, 256], then o2 = Linear(256, 256).
  8. Dropout, then add: x = x + crossattn(LN2(x), h).

Sublayer 3: MLP.

  1. x = x + Dropout(Linear(1024→256)(Dropout(GELU(Linear(256→1024)(LN3(x)))))), on each card by itself. This is where the card turns what it gathered in steps 1–17 into new features. The encoder's MLP uses ReLU; this one uses GELU (section 4 compares them).

The output has the same shape as the input, [B, 45, 15, 256], so it goes straight into the next block. After 3 blocks each card has compared itself with its pack three times and looked back at the draft three times, each round building on the last.

Why each step is there

Self-attention within the pack. The tensor is reshaped to [B·45, 15, 256], so each pack becomes its own tiny sequence of 15 tokens and packs never see each other. This answers questions like "is this the only red card here?" A card's value depends on what else it is competing with.

Cross-attention to the history. Queries come from the cards, keys and values from the history states. The 45×15 cards are flattened into one axis of 675 queries, and the 45-row mask is repeated 15 times (repeat_interleave) so every card at slot t gets row t. The state h_t already went into each card through state_proj. Cross-attention adds the option to look up specific earlier moments, such as the picks where the drafter took a creature at this mana value.

Mask convention flips between the two halves. The encoder uses nn.TransformerEncoder, where a boolean mask value of True means blocked, so it gets causal (True above the diagonal).

The decoder calls F.scaled_dot_product_attention directly, where True means allowed. So it gets pad = cnt > 0 and see = ~causal. Mixing these up is a common bug: the model trains fine while peeking at the future.

# Block.forward, picknet.py
q, k, v = self._heads(self.qkv(self.ln1(x)).reshape(B * T, P, 3 * d)).chunk(3, -1)  # [BT, 8, 15, 32]
a = F.scaled_dot_product_attention(q, k, v, attn_mask=pad.reshape(B * T, 1, 1, P))
x = x + self.drop(self.o1(a.transpose(1, 2).reshape(B, T, P, d)))

q = self._heads(self.q2(self.ln2(x)).reshape(B, T * P, d))     # [B, 8, 675, 32]
k, v = self._heads(self.kv2(mem)).chunk(2, -1)                 # [B, 8, 45, 32]
m = mem_mask.repeat_interleave(P, 0)                           # [675, 45]
a = F.scaled_dot_product_attention(q, k, v, attn_mask=m)
x = x + self.drop(self.o2(a.transpose(1, 2).reshape(B, T, P, d)))

return x + self.drop(self.mlp(self.ln3(x)))

From card vectors to a pick probability

  1. Score MLP. head = LayerNorm → Linear(256, 256) → GELU → Linear(256, 1), on each card by itself. Then drop the last axis: [B, 45, 15, 256] → [B, 45, 15]. Each number is a raw score (a logit) for that card at that pick. On its own the number means nothing; only differences within a pack matter.
  2. Mask empty slots. Where cnt == 0, set the logit to −∞, so those slots get probability 0.
  3. Log-softmax over the 15 slots. Each row of 15 becomes log-probabilities that sum (as probabilities) to 1. A pack with 3 cards left is a 3-way choice.
  4. Pick out the human's card. target ([B, 45]) is the slot the human took. gather pulls out its log-probability, and the negative of that is the loss for that pick: near 0 if the model gave the card high probability, large if it thought the card unlikely.
  5. Average. Mean over every valid pick in the batch (missing P1P1s are skipped). That is nll; the training loss is nll + 0.3 · deck.

At inference the same pass runs and the model's pick is just the card with the highest probability. Because all 45 picks are scored together and the masks stop any pick from seeing the future, one forward pass gives the same answers as running the model 45 times, one pick at a time.

4 · Inside the MLP

Every encoder layer and every decoder block ends with the same small network: Linear(256 → 1024), an activation, Linear(1024 → 256). It holds two thirds of each layer's weights, so it is worth knowing exactly what it computes.

Attention moves information between tokens. The MLP then works on each token alone: it reads one 256-number vector and writes back a 256-number change, with no idea what the other tokens hold. A common way to say it: attention is communication, the MLP is computation.

One hidden unit at a time

Follow one hidden unit i through the computation. It is the whole MLP, repeated 1024 times and summed:

  1. Measure. Take a dot product of the input z with row i of W1 and add a bias: s_i = w_i · z + b_i. This is one number saying how well z matches the pattern w_i.
  2. Gate. Pass it through the activation: a_i = ReLU(s_i) = max(0, s_i). If the pattern is absent (s_i ≤ 0), the unit is off and contributes nothing.
  3. Write. Multiply column i of W2 by a_i and add it to the output. Column i is a fixed 256-number direction that this unit always writes along; only the amount changes.

So the output is b2 + Σᵢ aᵢ · W2[:, i]: a sum of up to 1024 stored vectors, each switched on and scaled by how strongly its pattern appears. That is why people describe MLP layers as key–value memories: rows of W1 are keys, columns of W2 are values. In this model a unit might learn to fire on "many red picks and we're in pack 2" and write a direction that later layers read as "committed to red". That is an illustration of the kind of thing units do; it isn't something measured in this model.

The same thing as matrices

hidden = z @ W1.T + b1        # [N, 256]  @ [256, 1024] -> [N, 1024]   262,144 weights + 1,024 biases
hidden = relu(hidden)         # elementwise, no weights; GELU in the decoder
hidden = dropout(hidden)      # 5% of hidden units zeroed, training only
out    = hidden @ W2.T + b2   # [N, 1024] @ [1024, 256] -> [N, 256]    262,144 weights + 256 biases
x      = x + dropout(out)     # residual add: the MLP writes a change, it does not replace x

Only unit 1 fired, so the output is just its write vector times 2, plus the bias. Feed in a different z and a different set of units fires, giving a different sum. That input-dependent switching is the whole source of the MLP's power.

Why the activation is not optional

Remove the ReLU and the two layers collapse into one:

W2 (W1 z + b1) + b2  =  (W2 W1) z + (W2 b1 + b2)  =  W z + b      # one 256×256 linear map

All 525,568 weights would then do the job of a single 256×256 matrix, and the 1024-wide middle would buy nothing. Stacking linear maps is still linear. The activation is what lets the network represent "if this, then that": unit 1 fires and unit 2 doesn't.

ReLU and GELU

  • ReLU = max(0, x). Cheap, and exactly zero for negative inputs. A unit whose input is negative for every example gets zero gradient and can never recover: a dead ReLU.
  • GELU = x · Φ(x), where Φ is the standard normal CDF. It weights the input by "how likely is it to be positive". It is smooth, lets a little negative signal and gradient through, and is the default in BERT and GPT-2.
  • SwiGLU, used in LLaMA and most recent LLMs, replaces the activation with a gate: (Swish(z W_a) ⊙ z W_b) W_2. That needs three matrices instead of two, so the hidden width is usually cut to about 8/3·d to keep the weight count the same.

Why 4× wider in the middle

Each hidden unit is one pattern detector with one write direction. 1024 units means 1024 patterns per layer. The 4× ratio comes from the original Transformer paper (512 → 2048) and has stuck because it works; it is a convention, not a law. The cost is weights: 2 · 256 · 1024 ≈ 524k, against 4 · 256² ≈ 262k for attention. That is why the MLP is about two thirds of every layer in the table below.

The remaining 1.77M are the input side (card table, bag projections, position, set and context vectors) plus a 65,792-weight pool layer that only the no-history ablation uses. A useful check is that a transformer layer has about 12·d² weights: 4d² in attention (Q, K, V, O) and 8d² in a 4× MLP. With d = 256 that is 786k, close to the 789,760 counted here. A decoder block adds a second attention, so it has about 16·d².

Questions to practise on this model

  1. Why does token t contain pick t−1 and not pick t? What breaks if you shift it by one?
  2. Why is the diagonal of the causal mask left open, and what would a fully masked row do to the softmax?
  3. The decoder adds state_proj(h_t) to each card and cross-attends to all of h. What does each path give that the other does not?
  4. Why is there no position embedding on the candidate cards? What property does that give the decoder?
  5. Why is the deck head trained with binary cross-entropy while the pick uses a softmax?
  6. Why weight later states more in the deck loss?
  7. Self-attention in the decoder costs O(P²) per slot and cross-attention O(P·T). Which dominates here, and how does that compare to the encoder's O(T²)?
  8. Name both mask conventions in PyTorch and say which call in this file uses which.
  9. What happens to an MLP if you delete the activation? Show it with the algebra.
  10. What is a dead ReLU, and how does GELU avoid it?
  11. Why does the MLP hold most of a transformer layer's weights?
